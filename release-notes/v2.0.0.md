smpmon 2.0 monitors other machines. It can record history and look back through it, raise alerts, and feed Prometheus.

## Highlights

**Remote monitoring over SSH.** `smpmon connect deploy@web1` shows another machine exactly like this one. smpmon runs `smpmon agent --stdio` on the server through your `ssh`, so keys, `ssh-agent`, `~/.ssh/config` and jump hosts all work. Nothing listens on the network, and only the data on screen is collected. `--install` puts smpmon on the server: it copies this binary when the platform matches and otherwise downloads the right release and checks its checksum.

**Several hosts at once.** Hosts listed under `hosts:` in the config connect when smpmon starts:
- `H` switches every dashboard to another host.
- The new Hosts dashboard shows a card per server with CPU, memory, disk, network, load and latency.
- `source: web1` on a widget puts different hosts side by side on one dashboard.
- When a host goes offline, its last data stays on screen and smpmon reconnects by itself.
- Processes on remote hosts can be killed and reniced. Confirmations name the host.

**Network agent.** For machines you can't reach over SSH, run `smpmon agent --listen`. Connections use TLS, a read-only token and an optional control token that also allows kill and renice. Clients can pin the server certificate. `gen-cert` and `gen-token` set this up, and the deb and rpm packages include a systemd unit, disabled by default.

**History.** With `history.enabled`, metrics are written to disk at three resolutions, together with the top processes every 10 seconds. `[` and `]` move through time and `w` changes the window from 10 minutes up to 7 days. Every dashboard then shows the recorded window, and the process table shows what was running at that moment. The files are compact: slowly changing metrics take about a byte per value.

**Alerts.** Rules like `disk.fs.*.used_percent > 90` with `for`, hysteresis and cooldown are evaluated per series and per host. When a rule fires, smpmon shows a message, keeps a badge in the top bar and highlights the affected widgets; the new `alerts` widget lists them. Alerts can also go to desktop notifications, a command or a webhook.

**Export.** `--prometheus :9101` serves a `/metrics` endpoint with conventional names and labels. `smpmon stream` prints JSON lines. `smpmon headless` runs collection, history, alerts and export without the UI.

## Upgrading from 1.x

Configs from 1.x keep working, and the new features are off until you configure them. To monitor servers over SSH, smpmon 2.0 must run on both ends: run `smpmon connect --install <host>` once per server.

## Known limitations

- Windows: the agent can't run as a Windows service yet, and desktop notifications for alerts have not been tested.
- The network agent starts a separate collection for every connected client, so many clients on one agent cost proportionally more.
- With `--prometheus` in UI mode, only what the UI is collecting is exported. Use `smpmon headless` for a complete exporter.
